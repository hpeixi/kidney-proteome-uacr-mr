# 补齐 Zenodo 归档快照的操作步骤

## 先厘清一件事

Zenodo 的归档快照是**不可修改**的：v1.0.0 一旦发布，里面的文件就固定了。现在 v1.0.0 的快照里缺 `LICENSE` 与 `.zenodo.json`，且内容都在子文件夹 `发布包_kidney-proteome-uacr-mr/` 下。

因此"补齐"只有两种含义，对应两种操作：

| 需求 | 能否直接改 v1.0.0 | 做法 |
|---|---|---|
| 改标题、作者、描述、许可等**元数据** | 可以 | Zenodo 记录页右上角 Edit，改完 Save |
| 补文件、改目录结构 | 不可以 | 修好 GitHub 仓库后**发新 Release（v1.0.1）**，Zenodo 自动生成新版本 |

下面只说第二种，即真正"补齐快照"。

## 步骤一：把文件铺到仓库根目录

当前状态（已实测）：根目录只有 `README.md`（1,148 字节），`.zenodo.json`、`LICENSE`、`analysis/` 都是 404，内容都在子文件夹里。

1. 解压本地发布包 `发布包_kidney-proteome-uacr-mr.zip`（1,011,826 字节，36 个条目）。解压后根层应有：`.zenodo.json`、`DOI_获取步骤.md`、`GitHub上传操作指南.md`、`LICENSE`、`README.md`，以及 `analysis/`、`figures/`、`metadata/`、`results/` 四个目录。
2. 打开仓库根目录，点 **Add file → Upload files**。
3. 在资源管理器里勾选"显示隐藏文件"，**全选解压出来的内容**（不是外层文件夹），拖进上传区。
4. 提交说明写 `v1.0.1: flatten layout, add LICENSE and .zenodo.json`，点 **Commit changes**。

## 步骤二：删掉旧的子文件夹

进入 `发布包_kidney-proteome-uacr-mr/` → 右上角 `...` → **Delete directory** → Commit。

删完后根目录应正好是 5 个文件 + 4 个目录。

## 步骤三：发新 Release

仓库 → **Releases** → **Draft a new release** → Tag 填 `v1.0.1`（选 main 分支）→ **Publish release**。

Zenodo 会自动把 v1.0.1 归档为同一记录的**新版本**：

- **版本 DOI** 会变（形如 `10.5281/zenodo.xxxxxxx`，v1.0.0 为 `10.5281/zenodo.23851409`）；
- **概念 DOI**（Concept DOI）不变，指向"所有版本"。

## 步骤四：核对

1. 仓库首页：`README.md`、`LICENSE`、`.zenodo.json`、`DOI_获取步骤.md`、`GitHub上传操作指南.md` + `analysis/`、`figures/`、`metadata/`、`results/`。
2. `https://github.com/hpeixi/kidney-proteome-uacr-mr/blob/main/LICENSE` 应返回 200。
3. Zenodo 记录页会出现 **Versions**（v1.0.0、v1.0.1），v1.0.1 的许可、文件数都正确。

## 步骤五：把新 DOI 告诉我

我改三处并重新生成稿件：

1. `repo/metadata/CITATION.cff` 的 `doi`；
2. `repo/metadata/DOI.txt`；
3. 稿件 Declarations 的数据可用性声明。

引用建议：论文正文用**概念 DOI**（读者总能找到最新版），或在 CITATION 里同时写概念 DOI 与版本 DOI，二者保持一处在文中出现即可，不要混用。

## 常见问题

- **能只补文件、不改版本号吗？** 不能。Zenodo 的新快照只能由新 Release 触发。
- **删掉 v1.0.0 记录会怎样？** 不要删。已发表的 DOI 必须保持可解析。
- **`.zenodo.json` 一定要上传吗？** 不是必须，但上传后 Zenodo 会自动读取标题、作者、许可，省去每次手工填。
- **上传后网站看不到 `.zenodo.json`？** Windows 默认隐藏点开头文件，需在"查看"里勾选"隐藏的项目"。
